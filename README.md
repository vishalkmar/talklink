# TalkLink backend

Node.js 24 + Express 5 + Socket.IO + MongoDB + Redis. JavaScript only.
REST API under `/api/v1`, Socket.IO on the same port, health check at `/health`.

## Run locally
Needs a MongoDB **replica set** (transactions) and Redis.

```bash
npm install
cp .env.example .env        # fill JWT secrets; MONGO_URI / REDIS_URL point at your local or cloud DBs
npm run seed                # optional: 5 test users
npm run dev                 # http://localhost:4000/health
```
With `DEV_OTP_BYPASS=true` (development only) the login code `000000` works without email.

## Tests
```bash
npm test                    # uses database talklink_test + Redis db 15 only
npm run test:coverage
npm run lint
npm run check:secrets       # nothing secret is committed
```
Defaults: `mongodb://127.0.0.1:27017/talklink_test?replicaSet=rs0&directConnection=true` and
`redis://127.0.0.1:6380/15`; override with `TEST_MONGO_URI` / `TEST_REDIS_URL`.

## Deploy on Render
1. Push this folder to its own GitHub repo (see "Own repo" below).
2. **MongoDB Atlas** (free tier works): create a cluster, a database user, Network Access ->
   allow `0.0.0.0/0` (Render has no fixed IP on lower plans), copy the `mongodb+srv://...`
   connection string, add the database name: `.../talklink?retryWrites=true&w=majority`.
3. Render -> **New -> Blueprint** -> pick the repo. `render.yaml` creates:
   - `talklink-api` web service (`npm ci --omit=dev`, `npm start`, health check `/health`)
   - `talklink-redis` Key Value (Redis) - its URL goes into `REDIS_URL` automatically
   - JWT secrets are generated by Render.
4. Fill the asked values (you can leave any empty and add later - the server starts and logs
   which features are off):
   | Variable | Needed for |
   |---|---|
   | `MONGO_URI` | **required** |
   | `BREVO_API_KEY`, `BREVO_SENDER_EMAIL` | email login codes - **without them nobody can log in on production** |
   | `TURN_HOST`, `TURN_SECRET` | calls between different networks (Wi-Fi <-> mobile data) |
   | `FIREBASE_SERVICE_ACCOUNT` (base64 of the JSON) | incoming calls / messages while the app is closed |
   | `CASHFREE_*` | payments |
   | `ADMOB_AD_UNIT_IDS` | rewarded-ad verification |
   | `SUPPORT_EMAIL`, `FEEDBACK_TO_EMAIL`, `SENTRY_DSN`, `ADMIN_API_KEY` | optional |
   Every other variable has a sensible default (see `.env.example`).
5. After the first deploy: `https://<service>.onrender.com/health` should return `"status":"ok"`.
6. In the app (`App/.env`): `API_URL=https://<service>.onrender.com/api/v1` and
   `SOCKET_URL=https://<service>.onrender.com`, then rebuild the APK.
7. Cashfree dashboard -> webhook URL `https://<service>.onrender.com/api/v1/payments/webhook`;
   AdMob SSV callback `https://<service>.onrender.com/api/v1/ads/ssv`.

Notes:
- Use a **paid instance** (Starter). Free instances sleep after 15 minutes without traffic:
  sockets drop, the first request takes ~1 minute, and the scheduled jobs (streak reset at
  00:05 IST, 8 PM reminders, premium expiry) don't run while asleep.
- Every push to the connected branch redeploys automatically; roll back from the Render
  dashboard (Events -> previous deploy -> Rollback).
- Logs: Render dashboard -> Logs (JSON lines; search by `requestId` or `userId`).
- TURN: Render can't run a TURN server (needs UDP). Use a TURN provider that supports the
  shared-secret (coturn REST) scheme, or a small VPS with coturn, and put its host + secret here.

## Own repo (with history)
From the parent TalkLink repo:
```bash
git subtree split --prefix=backend -b backend-only
git push https://github.com/<you>/talklink-backend.git backend-only:main
```
Or simply copy this folder into a new repo - it has everything it needs.

## Layout
`src/` app code (config, routes, controllers, services, sockets, jobs, models), `tests/`
node:test suites, `scripts/` seed / load test / E2E peer / secret check, `static/avatars`.
API reference: `docs/API.md` and `docs/SOCKET_EVENTS.md` in the main TalkLink repo.
